# 8. A Google Cloud equivalent for every piece, and what we actually move

Date: 2026-11-23

Status: Accepted

## Context

Lab 7 left the whole system on AWS and described in Terraform (`infra/`, state in HCP
Terraform). Lab 9 asks the question an architect eventually gets asked out loud: what would it
take to run this on another cloud, and what would it cost?

Two constraints shaped the answer more than any technical argument:

- **There is no billing account.** The Google Cloud project `onetwotree-511013` exists and its
  APIs can be enabled, but `gcloud billing projects describe` reports `billingEnabled: false`,
  and the one billing account on the e-mail is `OPEN: False` - the free trial asks for a
  prepayment in this country. So `gcp/` is a configuration that is written, initialised and
  validated, but never applied. Everything below is a decision about a design, not a report on
  a running system.
- **Moving everything was never the goal.** The lab moves the part that makes the app usable:
  the frontend, the API and the database. Sign-in, the weekly report and the agenda parser stay
  on AWS. That is not a shortcut - it is the normal shape of a migration, and the interesting
  decisions are at the seam.

## Decision

### The table, decided row by row

`keep` = stays on AWS, `replace` = moves to the GCP service named, `drop` = not rebuilt.

| What we run on AWS | On Google Cloud | Decision | Why |
| --- | --- | --- | --- |
| S3 + CloudFront, static SPA (`infra/frontend.yaml`) | Firebase Hosting | **replace** | One service instead of three: bucket, CDN and managed certificate. The free plan (10 GB stored, 360 MB/day out) covers a 1 MB SPA and a term of class demos. A bare Cloud Storage bucket was rejected: it serves no HTTPS on a custom domain without a load balancer, and a load balancer bills by the hour whether anyone visits or not. |
| AWS WAF on the distribution | Cloud Armor | **drop** | Cloud Armor needs that same hourly load balancer, so on GCP the WAF stops being free. CloudFront's Free plan bundled it; Firebase Hosting has no equivalent. Recorded as a real loss, not an oversight. |
| Lambda + function URL, FastAPI via Mangum (`infra/backend.yaml`) | Cloud Run | **replace** | The adapter disappears. Lambda needed Mangum to turn event JSON into ASGI; Cloud Run sends HTTP to `$PORT`, so `back/Dockerfile.cloudrun` is plain uvicorn and the identical image runs on a laptop. Also no 15-minute ceiling and no 250 MB unzipped limit. |
| ECR (`infra/backend-ecr.yaml`) | Artifact Registry | **replace** | Like for like. 0.5 GB free, which one ~250 MB image fits and three do not, so `gcp/registry.tf` keeps the three most recent versions and deletes the rest. |
| Aurora Serverless v2, 0-1 ACU, pauses | Cloud SQL for PostgreSQL, `db-f1-micro` | **replace**, with eyes open | The one row where GCP is strictly worse for us. Discussed below. |
| DynamoDB | Firestore | **not applicable** | We never moved off SQL. The option is still analysed below, because it is the only way to get the database line to $0. |
| Cognito user pool + Google IdP (`infra/auth.tf`, `infra/cognito.yaml`) | Identity Platform | **keep** | 50,000 free MAU against Cognito's 10,000 is the better deal, and we still will not take it: Cognito cannot export password hashes. Migrating the pool means every existing user resets their password. A stretch goal, not a migration step. |
| EventBridge Scheduler (`infra/reports.tf`) | Cloud Scheduler | **keep** | Moves in one resource (3 jobs free, then $0.10/job/month), but it only makes sense together with the rest of the report chain, which stays. |
| SQS (`infra/reports.tf`) | Pub/Sub or Cloud Tasks | **keep** | If it did move: Cloud Tasks, not Pub/Sub. The queue holds one unit of work per week for one consumer, which is a work queue, not a fan-out topic. |
| S3 event -> mailer Lambda (`infra/reports.tf`) | Cloud Storage + Eventarc -> Cloud Run | **keep** | Same shape, one more service in the path (Eventarc). No reason to re-wire it while the report itself stays. |
| SES for the weekly report | no Google service | **keep** | There is nothing to move to. Google runs no transactional e-mail service; the alternatives are SendGrid or Mailgun. Discussed below. |
| Bedrock, Claude for the agenda parser (`infra/ai.tf`) | Vertex AI, Claude through Model Garden | **keep** | The same models are reachable, and the trial credit explicitly does not pay for partner models on Vertex AI. Moving it would cost real money to run a feature that currently runs on credit. |
| Secrets Manager / SSM | Secret Manager | **replace** (GCP side only) | The Cloud SQL password is generated by Terraform and written to Secret Manager; Cloud Run reads it as an environment variable through `value_source`. 6 active versions free. The AWS secrets stay where they are. |
| CloudWatch Logs | Cloud Logging | **replace** | Automatic, and the one IAM grant worth not forgetting (`roles/logging.logWriter`) - without it the service runs and says nothing. |
| IAM roles | Service accounts + IAM roles | **replace** | One service account per program, as Part 0 asks. `gcp/iam.tf` creates the runtime identity only: Cloud SQL client, one secret, its own logs. It deliberately cannot deploy. The deployer identity is created by hand, because a configuration able to mint its own deployer is a configuration able to grant itself anything. |
| Terraform `aws` provider, HCP workspace `meetings-dev` | Terraform `google` provider | **replace**, separate state | `gcp/` is its own root module with its own state, so no single plan can touch both clouds. |

### The database

Four options, and the deciding factor is not the price.

**Cloud SQL `db-f1-micro` around the clock - $7.67/month compute plus $1.70 storage.** The honest
comparison: Aurora Serverless v2 at 0 ACU costs $0 when nobody uses the app, and `db-f1-micro`
has no idle state at all. It runs and it bills until somebody stops it. This is the single line
that decides the whole cost comparison (see `docs/lab9-costs.md`).

**Cloud SQL stopped between demos - $1.70/month.** Storage is billed whether the instance runs or
not, so stopping it is a 78% saving, not a 100% one. `gcp/outputs.tf` prints the exact command
as `stop_database_command`, because this is the line that ends up on a student's bill.

**Firestore - $0/month at this traffic.** 50,000 reads a day free is about 1.5 million a month,
and this app would not come close. Rejected, and not because of the price:

- The schema is relational and used relationally. `User`, `Meeting` (with `owner_id`),
  `Participant`, and `meeting_participants` as a join table. The week view is a range query over
  meetings joined to their participants. Firestore has no joins, so every meeting document
  would carry a copy of its participants, and a renamed participant becomes a fan-out write
  across every meeting they ever attended.
- It is not a config change, it is a rewrite. `app/models.py`, everything in `app/services/`,
  and the four Alembic migrations all encode SQL. The weekly report (`app/reports/weekly.py`)
  is a SQL aggregation that produces a CSV; in Firestore it becomes application code that reads
  documents and counts them.
- The saving is $9.37 a month. The rewrite is days of work on the only part of the system that
  holds the data, for an app with no users yet. Wrong trade.

**Keep the database on AWS and call it across clouds.** Rejected on three counts. Latency: Cloud
Run in `us-central1` to Aurora in `us-east-1` is roughly 25-30 ms per round trip, and the API
opens a connection per request, so the handshake pays that several times over before the first
row. Money: egress is charged on both sides of every query. Security: Aurora sits in private
subnets with no public endpoint, so this would mean either exposing it to the internet or
building a VPN between the clouds - more moving parts than the whole rest of this lab.

**Decision: Cloud SQL `db-f1-micro`, 10 GB SSD, stopped when nobody is demoing.** It keeps the
code identical - `app/config.py` already builds its URL from `DB_*` parts, and libpq reads a
host beginning with `/` as a socket directory, so the Cloud SQL unix socket needs no code change
at all - and it keeps the migration honest. Firestore is recorded as the answer if this ever
needs to cost nothing while running unattended.

### E-mail

**SES stays, and that is partly a security argument.** SES authenticates with IAM, so there is no
API key anywhere: the report Lambda's role is the credential. The moment we move to SendGrid or
Mailgun we acquire a long-lived secret that has to be stored, rotated and kept out of the
repository - the exact class of credential Part 0 spends its length telling us to avoid.

If it did move, the key would live in **Secret Manager** and reach Cloud Run through
`value_source.secret_key_ref`, the same way the database password does in `gcp/run.tf`. Never a
build argument, never in `firebase.json`, and never in the SPA - a key in a frontend bundle is a
public key with extra steps.

### What we would not move, and why

- **The agenda parser.** Bedrock with Claude, behind a function URL with its own token check.
  Vertex AI offers the same models, but the trial credit does not cover partner models, so
  moving a feature that currently runs on credit would start costing cash. There is also nothing
  to gain: it is one stateless function with no database.
- **The weekly report.** Scheduler, a queue, a bucket, a bucket event, a mailer and SES: six
  pieces, each with a GCP counterpart, for a job that runs once a week and costs cents. The
  counterpart of SES does not exist, so a "full" migration still leaves an AWS dependency - or
  acquires a third-party one. Not worth it.
- **Sign-in.** Identity Platform's free tier is five times Cognito's, and the blocker is the
  password hashes: Cognito will not export them. A migration costs every user a password reset.
  The number that would change this is a Cognito bill above 10,000 MAU, which this app is a long
  way from.

## Consequences

- Two clouds, permanently, not transitionally. The frontend, API and database on Google Cloud;
  auth, reports and the parser on AWS. The ID token is the seam: the Cloud Run service verifies
  tokens issued by a Cognito pool in another cloud, which works because JWT verification needs
  only the issuer's public keys over HTTPS.
- Two Terraform states that must not drift into each other. `infra/` keeps the AWS resources
  and the Cognito pool; `gcp/` takes `var.cognito_user_pool_id` as an input. A pool rebuilt on
  the AWS side is a variable change on the GCP side, and nothing enforces that but this
  sentence.
- The bill goes from about $0.30 a month to about $9.40, or $1.70 with the database stopped. The
  only line responsible is Cloud SQL compute. On AWS the same app idles at nearly zero because
  Aurora pauses.
- The WAF is gone, and the frontend is slightly less defended than it was on CloudFront's Free
  plan.
- `back/app/main.py` no longer imports Mangum. The adapter moved to `app/lambda_handler.py`,
  which already had its own, and `back/serverless.yml` was corrected to point there. The Lambda
  path is unchanged; the Cloud Run image simply never installs mangum.
